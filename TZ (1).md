# Техническое задание

**на разработку консольной программы «Сумма элементов массива, кратных K»**

| Поле | Значение |
|---|---|
| Версия документа | 1.0 |
| Дата | 21.10.2026 |
| Исполнитель | _ФИО студента, группа_ |
| Заказчик | _ФИО преподавателя / организация_ |

## 1. Общие сведения

### 1.1 Наименование
Консольная программа «Array Sum» для вычисления суммы элементов целочисленного массива, делящихся без остатка на заданное число K, с резервным копированием входных данных.

### 1.2 Основание для разработки
Учебное задание: создание консольной программы на языке Python с возможным вводом и выводом данных через файл и через консоль для нахождения суммы всех элементов целочисленного массива, которые делятся без остатка на заданное пользователем число K.

### 1.3 Термины
- **Массив** — последовательность целых чисел (положительных, отрицательных, нулей).
- **K** — целый делитель, заданный пользователем, K ≠ 0.
- **Кратный элемент** — элемент `x`, для которого `x % K == 0`.
- **Резервная копия** — файл формата JSON с копией входного массива, датой создания и контрольной суммой SHA-256.

## 2. Цель и назначение
Автоматизировать вычисление суммы элементов массива, кратных K, и обеспечить сохранность входных данных: возможность создать копию массива и восстановить его при потере или повреждении файла.

## 3. Требования к программе

### 3.1 Функциональные требования

| № | Требование |
|---|---|
| FR-1 | Вычисление суммы элементов массива, делящихся на K без остатка; вывод самих подходящих элементов и суммы. |
| FR-2 | Ввод массива и K через консоль: интерактивное меню и аргументы командной строки. |
| FR-3 | Ввод массива из текстового файла (UTF-8); числа разделяются пробелами и/или переводами строк. |
| FR-4 | Вывод результата в консоль и в текстовый файл `output.txt` (или в файл, указанный пользователем). |
| FR-5 | Массив должен быть непустым и состоять только из целых чисел; допускаются отрицательные числа и ноль. |
| FR-6 | K — целое число, не равное нулю; допускается отрицательное K. |
| FR-7 | Если подходящих элементов нет, сумма равна 0, в результате выводится «нет». |
| FR-8 | Создание резервной копии файла входных данных `input.txt`; перед копированием содержимое проверяется, копия некорректных данных не создаётся. |
| FR-9 | Восстановление `input.txt` из выбранной или последней резервной копии с проверкой контрольной суммы и структуры данных. |
| FR-10 | Перед восстановлением автоматически создаётся страховочная копия текущего `input.txt` (если он есть и корректен). |
| FR-11 | Хранится не более 10 последних резервных копий, более старые удаляются. |
| FR-12 | При любой ошибке исходные данные не изменяются, а пользователь получает понятное сообщение. |

### 3.2 Нефункциональные требования

| № | Требование |
|---|---|
| NFR-1 | Python 3.8 и выше, только стандартная библиотека. |
| NFR-2 | Работа на Windows, Linux, macOS. |
| NFR-3 | Запись файлов выполняется атомарно (через временный файл). |
| NFR-4 | Некорректные данные не приводят к аварийному завершению с traceback; код возврата при ошибке — 1. |
| NFR-5 | Обработка массива из 1 000 000 элементов — менее 1 секунды. |
| NFR-6 | Пользовательский интерфейс и сообщения на русском языке. |

### 3.3 Алгоритм вычисления
1. Проверить, что массив не пуст и состоит из целых чисел; проверить, что K — целое и K ≠ 0.
2. Для каждого элемента `x`: если `x % K == 0`, добавить `x` в список подходящих.
3. Сумма = сумма списка подходящих элементов (0, если список пуст).

Нулевой элемент делится на любое K ≠ 0 и учитывается (на сумму не влияет). Для отрицательных чисел используется математическая кратность: `-12 % 4 == 0`.

### 3.4 Алгоритм резервного копирования и восстановления

**Копирование:**
1. Прочитать `input.txt` и проверить содержимое (FR-5). Ошибка — копия не создаётся.
2. Сформировать JSON `{created, checksum, data: {numbers}}`, где `checksum` — SHA-256 от `data`.
3. Атомарно записать в `backups/<дата_время>_<тип>.json` (тип `manual` или `pre-restore`).
4. Удалить копии сверх лимита 10 (самые старые).

**Восстановление:**
1. Найти копию (`latest` или указанное имя). Копий нет или имя неверное — ошибка.
2. Прочитать JSON, сверить SHA-256, проверить, что массив непустой и целочисленный. При ошибке `input.txt` не изменяется.
3. Если `input.txt` существует и корректен, сохранить его как `pre-restore`.
4. Атомарно записать массив в `input.txt`.

### 3.5 Форматы данных
**`input.txt`:** `4 7 12 15 20` (числа через пробелы или переводы строк).
**`output.txt`:**
```
Исходный массив: 4 7 12 15 20
Делитель K: 4
Подходящие элементы: 4 12 20
Сумма: 36
```
**Резервная копия:**
```json
{ "created": "2026-10-21T12:00:00", "checksum": "<sha256>", "data": { "numbers": [4, 7, 12, 15, 20] } }
```
