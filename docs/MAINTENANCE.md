# Регламент технического обслуживания

Документ определяет порядок обслуживания программы «Array Sum» и её данных: входного файла `input.txt` и резервных копий в папке `backups/`.

## 1. Ответственность

| Роль | Обязанности |
|---|---|
| Пользователь / оператор | Создание резервных копий, проверка копий, ведение журнала обслуживания. |
| Администратор / разработчик | Обновления, запуск тестов, аварийное восстановление. |

## 2. Перед началом работы
- Проверить версию Python: `python --version` (нужен 3.8 или новее; на Linux/macOS — `python3`).
- Убедиться, что `main.py`, `input.txt` и папка `backups/` находятся в одной папке проекта.
- Проверить, что `input.txt` содержит только целые числа, и что на диске есть место для копии.

## 3. Плановые работы

| Периодичность | Работа | Команда / действие |
|---|---|---|
| Перед каждым изменением `input.txt` | Создать резервную копию | `python main.py backup` |
| Ежедневно (при работе с данными) | Создать копию и убедиться, что она появилась | `python main.py backup`, `python main.py backups` |
| Еженедельно | Проверить целостность всех копий (все со статусом «OK») | `python main.py backups` |
| Еженедельно | Проверить программу на контрольном примере (ожидается сумма 36) | `python main.py sum --array 4 7 12 15 20 --k 4` |
| Еженедельно | Скопировать папку `backups/` на внешний носитель или в облако | вручную |
| Ежемесячно | Проверить восстановление на тестовой копии проекта | `python main.py restore` |
| Ежемесячно | Запустить автоматические тесты | `python -m unittest discover -s tests -v` |
| После обновления Python или программы | Запустить тесты и ручные тест-кейсы | см. `docs/TEST_CASES.md` |

## 4. Порядок изменения входных данных
1. Создать резервную копию (`backup`).
2. Изменить `input.txt` (вручную или пунктом меню 4).
3. Проверить расчёт на контрольных данных.
4. Записать изменение в журнал (раздел 8).

## 5. Аварийное восстановление

| Сообщение / ситуация | Действия |
|---|---|
| `input.txt` удалён («Файл не найден») | `python main.py restore` |
| `input.txt` повреждён («не является целым числом», «Массив пуст») | `python main.py backups` → `python main.py restore` |
| Нужна конкретная версия | `python main.py restore <имя_файла>.json` (имя — из `backups`) |
| «контрольная сумма SHA-256 не совпала», «неверная структура копии», «файл повреждён» | Копия повреждена, `input.txt` не изменён. Выбрать другую копию со статусом OK (`backups`) или взять копию с внешнего носителя. |
| «Резервных копий нет» | Вернуть папку `backups/` с внешнего носителя; иначе создать `input.txt` заново. |
| Восстановили не ту версию | В `backups` найти файл с пометкой `[страховочная]` (состояние до восстановления) и выполнить `restore <имя_файла>.json`. |

## 6. Хранение и очистка
- Хранится не более 10 последних копий; более старые удаляются автоматически (копия, из которой идёт восстановление, не удаляется).
- Файлы копий вручную не редактировать и не переименовывать: нарушится контрольная сумма, и копия будет отклонена. Исключение — удаление ненужных копий целиком.
- Содержимое `backups/` и файл `output.txt` не публикуются в GitHub (настроено в `.gitignore`).
- Файлы `*.tmp` в папках проекта и `backups/` (остаются только после аварийного прерывания записи) можно удалить.

## 7. Обновление программы
1. Создать резервную копию (`backup`).
2. Получить новую версию: `git pull`.
3. Запустить автоматические тесты и контрольный пример.
4. При ошибках вернуться на предыдущую версию (`git checkout <тег или коммит>`) и сообщить разработчику.

Изменения проекта и документации фиксируются в GitHub с понятным сообщением к коммиту (см. `docs/GIT.md`).
